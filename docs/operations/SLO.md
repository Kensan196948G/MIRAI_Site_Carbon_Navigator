# SLO / アラート / エスカレーション

## SLI / SLO（初期値）

| SLI | 定義 | SLO（30日） |
|---|---|---|
| 可用性 | `/api/health` が200応答 | 99.5% |
| APIエラー率 | 5xx応答 / 全API応答 | < 0.5% |
| 応答時間 | API p95 | < 2.0秒 |
| バックアップ成功 | 日次バックアップ成功回数 / 日数 | 100%（1回/日） |
| データ鮮度 | 監視ログ最終更新 | < 10分 |

## アラート閾値と通知先

| レベル | 条件 | 通知先 | 対応期限 |
|---|---|---|---|
| 警告 | ヘルスチェック1回失敗 / p95 > 2s / エラー率 > 0.5% | 運用担当（Teams/SMTP設定時） | 4時間以内に確認 |
| 重大 | ヘルスチェック3回連続失敗 / 5xx率 > 5% / DB接続失敗 | 一次対応責任者へ電話・Teams | 30分以内にエスカレーション |
| 重大 | バックアップ失敗2日連続 | 一次対応責任者 | 24時間以内に復旧 |

## 一次対応責任者・エスカレーション

- 一次対応: プロジェクト管理者（本番環境を起動したオペレータ）
- エスカレーション1: アプリ/DB復旧担当（デプロイ・バックアップ担当）
- エスカレーション2: 開発リポジトリ管理者（GitHub オーナー Kensan196948G）
- 重大障害の連絡経路: 本リポジトリのIssue + Teams/SMTP（設定時）

## 通知試験

`POST /api/admin/notify-test`（admin）を実行し、`email_sent` / `teams_sent` の結果を確認する。
通知チャネル未設定の場合は「未設定」と判定し、導入時に再試験する。
