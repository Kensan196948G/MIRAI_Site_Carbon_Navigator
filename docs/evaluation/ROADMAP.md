# ロードマップ

## Phase 0: 重大問題・セキュリティ（今回実施 + 直近）

- 静的ファイル復旧、権限境界、TOTP 除外、OIDC code 交換、ログイン保護、既定アカウント制御、fail-closed entrypoint（実施済み）
- 残: Tunnel 復旧、既定アカウント無効化、通知チャネル設定
- 完了基準: 公開 URL 24h 連続可用、権限監査 PASS、障害通知到達確認

## Phase 1: 中核業務完成（3 か月以内）

- 2 現場実地 PoC と利用者受入テスト
- 排出係数の一次情報突合（環境省・電気事業者公表値）と更新手順
- Excel/SharePoint 提出フローと既存 M365 連携（Teams/SMTP）
- 主要画面のブラウザ E2E とアクセシビリティ監査
- 完了基準: PoC 受入テスト PASS、係数台帳の出典・更新日管理、E2E 実行

## Phase 2: 競合製品 80% 代替（6 か月以内）

- 監査ログ拡充（IP/UA・検索・エクスポート）と 3 年保持アーカイブ
- API 契約（OpenAPI ベース）と外部連携ドキュメント整備
- RBAC 棚卸し・四半期権限監査の自動化
- バックアップ暗号化・KMS 導入と四半期復元試験の定期化
- 完了基準: 代替率 80% 以上、監査・復旧手順の実証

## Phase 3: AI・モバイル・外部連携（6〜12 か月）

- AI: 文書 RAG（環境省ガイドライン・社内手順）による根拠付き検索、構造化抽出（伝票→活動量）、異常値の説明生成。LLM 導入時は権限制御・プロンプトインジェクション対策・入出力監査・人間承認・予算上限を必須
- モバイル: PWA（manifest・Service Worker・オフライン入力キュー）
- 連携: 建機・テレマティクス実接続、Neon PostgreSQL 移行、DirectCloud/DeskNet's NEO 等との疎通確認
- 完了基準: PoC ユーザー満足度調査、AI 誤判定の責任分界文書化

## Phase 4: 90% 代替・本番最適化（12 か月以降）

- 認証強化（リフレッシュトークン・失効・条件付きアクセス）
- 負荷試験・SLO ダッシュボード・障害自動復旧
- 第三者検証（脆弱性診断・保証レビュー）と ISO27001 等の監査対応
- 完了基準: SLO 達成実績、診断結果 0 critical、本番利用判定
